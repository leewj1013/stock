# 변경 내역과 판단 근거 보존

## 전일 대비 변경 내역

V1·V2 첫 화면의 접힌 상세 보기에서 위험관리·가격 확인 상태·보유종목 거래 상태·공시 일정·일정 수집 상태의 변경만 표시한다. `stock_alarm.investment_timeline`이 기존 장 시작·추천·매도·마감 작업에서 관측 상태를 `data/investment_timeline.db`에 저장한다. 화면 조회는 기준 상태를 변경하지 않는다.

기준은 전일 이전 마지막 저장이다. 전일 자료가 없는 첫날에는 첫 저장과 비교하고 이를 명시한다. 같은 상태의 반복 수집은 하루 내 중복 저장하지 않되 마지막 점검 시각은 갱신한다. 첫 관측 이전의 변경은 소급 추정하지 않는다. 오늘 수집이 없으면 마지막 저장 자료라고 표시한다.

정상 자료로 확인된 위험 상태 해소와 조회 실패·자료 누락을 구분한다. 매도로 보유 목록에서 빠진 종목은 위험 해소가 아니라 추적 종료다. 원문 정정·철회로 날짜가 미확정이 된 경우 일정·공시 변경으로 표시하며 새 날짜나 취소 확정을 추정하지 않는다.

## 판단 시점 기록

국내 DB 스키마 10의 `decision_evidence`에 선정 추천·매도 신호·가상매수·가상매도 근거를 추가 저장한다. 추천은 두 성향의 점수와 당시 후보 지표·실행 설정·성향 규칙을 보존한다. 체결은 실제 함수 입력, 수량·가격·대금, 당시 적용 설정을 보존하고 매도에는 전달된 성향별 정책·사유·익절 단계도 포함한다. 실계좌 주문을 추가하지 않는다.

체결 원장과 근거는 동일 SQLite 트랜잭션에 기록한다. 근거 저장에 실패하면 해당 가상 체결도 롤백되어 근거 없는 체결이나 고아 근거가 남지 않는다. 추천 실행이 실패한 경우에도 당시 관찰 사실은 남기되 화면에 실행 실패를 표시한다. 반복 저장은 첫 기록을 유지하고 UPDATE·DELETE 트리거로 덮어쓰기를 막는다. JSON SHA-256은 저장 내용의 일치 확인용이며 외부 서명을 뜻하지 않는다.

V1·V2 계좌 분석의 ‘판단 시점 기록’은 유형별 최근 5건을 먼저 표시한다. ‘당시 전체 기록 보기’를 펼치면 원래 입력·설정과 발생 시각·보존 시각·해시를 확인한다. 읽기 화면에서는 전체 기록을 HTML로 이스케이프한다.

초기 `python -m stock_alarm.decision_evidence --backfill`은 최근 300개 매수·매도와 최근 30개 추천 실행의 이미 저장된 자료만 복원한다. 복원 자료는 ‘기존 기록 복원’으로 구분하고, 당시 기록이 없는 입력·규칙을 현재 설정으로 채우지 않는다. 이후 새로 발생하는 판단은 ‘당시 저장’으로 구분한다. 기존 현금·수량·체결 원장은 수정하지 않는다.
