# 추가 관찰 실험 v1 (2026-10-19)

## 적용 순서

1. 미매수 사유: 정규 추천 실행의 auto_buy_virtual_trader 호출을 감싸 실제
   입력·초기 계좌·위험 판단·최종 체결을 관찰한다. 원래 함수를 같은 인수로 한 번
   호출하고 반환값과 예외를 그대로 유지한다. app.py, sell_check.py 등 미국
   동결 엔진 파일은 변경하지 않는다. 정규 python -m stock_alarm 진입점에서 적용하며
   대시보드의 수동 주문, app 모듈 직접 호출은 이 관찰 대상이 아니다.
2. 시장·업종: 실제 매수 계산에 사용된 시장 분류와 당시 업종 캐시를 보존한다.
   기존 매수 실험은 원본 추천 run_id로 연결하고, 매도 실험은 진입일·가격이
   유일하게 일치하는 실제 가상체결에만 연결한다. 매칭 불가/중복은 미확인으로 둔다.
   엔진은 시장 데이터 부족 시 횡보로 대체할 수 있으므로 해당 분류는 확정 시장
   진단이 아니다. 시점이 지난 뒤 최신 업종 정보로 과거 분류를 덮어쓰지 않는다.
3. 한도·최소 체결: 당시 정수 수량 예산 계산을 재현하여 실제 체결과 맞을 때만
   비교한다. 한도 +10%p(최대 100%)와 목표금액 대비 최소 체결 10%를 각각
   단독 적용하며 동시에 바꾸지 않는다. 위험중단은 해제하지 않는다.
4. 재진입: 관찰 시작 이후 실제 가상계좌 전량매도에 대해 현금 유지,
   3거래일 대기 후 다음 시가 진입, 2거래일 연속 20일선 위 종가 확인 후
   다음 시가 진입을 비교한다. 재진입은 1회이며 종가 -5% 이탈 다음 시가에 정리한다.
5. 교체: 당일 관측된 같은 계좌 성향 점수가 있는 보유 중 최저 점수와 새 추천
   최고 점수의 차이가 10점 이상이면 기존 보유 수량 25%를 정수로 잘라 다음
   거래일 시가에 교체하는 안을 계속 보유와 비교한다. 지표가 없으면 사례 생성 안 함.

## 기록 및 해석

data/portfolio_research.db에 실제 호출별 기록과 관찰 사례를 별도 저장한다.
빈 추천도 점검 기록으로 남긴다. 미매수 이유는 실제 함수의 초기 반환 조건 또는
관찰한 예산 계산을 재현한 분류다. 실제 체결이 우선이며 예측상 체결 가능인데
실제 체결이 없으면 확인 필요다. 현금·한도·최소 체결·1주 가격·기존 목표 충족,
상관관계·업종 제한을 구분하며 모든 미매수를 투자 한도 탓으로 단정하지 않는다.
로그 보존 실패는 매수/알림을 취소하지 않고 오류 로그에 남긴다.

금액·가격은 당시 입력, 시장 라벨은 호출 중 반환값, 업종은 캐시 시각을 함께 보존한다.
한도 실험은 당시 계산된 예산을 다음 시가에 비용 포함 정수 수량으로 다시 계산한다.
계좌 상태 전체가 이어지는 복제 계좌가 아니라 독립적인 거래 기회 비교다.
남는 자금은 현금 유지, 한도/교체 실험은 10거래일 보유 가정이며 재진입만 위 손절 적용.
모든 실험 비용은 매수/매도 각 15bp, 별도 슬리피지와 세금 차이는 미반영이다.
관찰 기간 끝 종가의 청산가치는 비교용 평가이지 실제 종가 체결이 아니다.

1/3/5/10거래일 중 완료된 기간만 계산한다. 당일 미완성 봉은 제외한다.
한도 사례는 계좌·종목·날짜별 최초 해당 기회, 교체는 계좌·날짜별 최초 해당 기회,
재진입은 실제 전량매도 건별로 중복을 막는다. 겹치는 관찰기간은 독립 표본이 아니다.
한도는 단일 종목의 계좌 기여도, 재진입은 매도대금 수익률, 교체는 동일 자금
수익률이므로 서로 합산하거나 하나의 전략 순위로 평균내지 않는다.

국내 적극/중립 계좌의 사례를 만들며 비교 전용 계좌의 호출은 감사 기록만 남긴다.
미국 전략은 별도 시장/시점 검증이 필요하여 포함하지 않는다.
정규 추천 때 입력 기록, 마감/유지보수 때 결과 갱신·백업을 수행한다.
수동 결과 갱신: python -m stock_alarm.portfolio_research
대시보드 전략 연구의 미매수 사유·계좌 운용 관찰과 시장·업종별 완료 성과에서 확인한다.
