# 대시보드 전체 감사 보고서

- 감사일: 2026-08-26
- 범위: 핵심 요약, 가상 트레이더, 수집 데이터, 상세 진단
- 방법: 현재 로컬 실행 화면, 접근성 트리, 표시 데이터, 관련 구현 코드 점검
- 주의: 이번 작업은 검토만 수행했으며 제품 코드는 변경하지 않았다.

## 결론

현재 대시보드는 데이터 자체는 풍부하지만, **서로 다른 의미의 데이터를 같은 용어로 보여주는 문제**, **정상/장애 판정의 신뢰성 문제**, **운영 데이터와 개발자용 원시 데이터의 혼재**가 크다. 화면 미관보다 데이터 의미와 상태 판정을 먼저 고쳐야 한다.

## P0 — 즉시 수정

1. **가상 트레이더의 `보유금액` 의미 수정**
   - 화면의 9,385,000원은 현금인데 `보유금액`으로 표시된다.
   - 실제 총자산은 현금 9,385,000원 + 보유주식 평가액 613,500원 = 9,998,500원이다.
   - `현금`, `주식 평가액`, `총자산`, `누적/평가 손익`을 각각 분리한다.

2. **상세 진단의 정상 판정 로직 수정**
   - 상단은 `문제 없음`, `오늘 실행 정상`이라고 표시하지만 같은 화면의 최근 발송에는 `notifier returned false`, `TimeoutError`가 있다.
   - 추천/매도/가상주문/시황/마감 등 필수 작업별 마지막 성공시각과 실패를 모두 포함해 상태를 계산해야 한다.
   - `문제 없음`은 치명적 오판이므로, 경고/장애/정상 3단계와 판정 근거를 표시한다.

3. **추천과 가상 주문 데이터의 용어·상태 완전 분리**
   - 핵심 요약의 `보유 종목`은 추천 추적 포지션이고 가상 트레이더 보유종목이 아니다.
   - 각각 `추천 성과 추적 종목`과 `가상계좌 보유종목`으로 명확히 이름을 바꾼다.
   - 추천 여부, 알림 성공 여부, 가상주문 여부를 별도 컬럼/상태로 유지한다.

4. **비중 정보의 시점과 규칙 명확화**
   - 오늘 추천 목록에 과거 산출값 100%가 남아 있어 현재 10~30% 규칙과 충돌해 보인다.
   - `당시 산출 비중`, `현재 주문 목표 비중`, `실제 체결 비중`을 분리하고, 규칙 변경 전 데이터에는 배지를 붙인다.

## P1 — 다음 수정 묶음

5. **가격·수익률 최신성 표시**
   - 모든 현재가/평가액에 `가격 기준시각`과 데이터 출처를 표시한다.
   - 자동 새로고침 또는 새로고침 버튼을 제공하고 실패 시 마지막 정상 가격임을 알린다.
   - 가상 트레이더 표에 `현재가`를 추가한다.

6. **자동매매 UX 정리**
   - 자동매매 상태(켜짐/꺼짐), 다음 점검시각, 오늘 주문 결과, 주문 실패 사유를 보여준다.
   - `추천 비중으로 매수` 수동 버튼은 자동주문과의 중복 가능성을 설명하거나 운영자 기능으로 분리한다.
   - 입금에는 명시적 라벨, 처리 중 상태, 성공 확인, 입출금/주문 이력을 제공한다.

7. **핵심 요약을 의사결정 중심으로 재구성**
   - 최우선 정보는 `시스템 상태`, `가상계좌 총자산/수익률`, `오늘 추천·주문·매도`, `마지막 가격시각`이다.
   - 긴 텔레그램 메시지는 카드에서 말줄임하고 상세에서 펼친다.
   - 8번째 카드가 혼자 다음 줄로 내려가는 그리드를 수정한다.

8. **수집 데이터 화면을 운영자용으로 정리**
   - 104,448 등 KPI가 누적인지 오늘인지 명시한다.
   - 22열 원시 테이블은 핵심 컬럼 기본 표시 + 상세 펼치기로 바꾼다.
   - 검색, 날짜, 종목, 실행유형, 상태, 탈락사유 필터를 추가한다.
   - 부동소수점은 의미에 맞게 2~4자리로 반올림하고 종목명 언어를 통일한다.
   - `volume_ratio`, `sell_check`, `completed` 같은 내부 코드는 사용자용 한국어로 번역한다.

9. **상세 진단 정보 구조 개선**
   - `상태 요약 → 실패/경고 → 마지막 성공시각 → 설정 → 원시 로그` 순으로 배치한다.
   - 현재의 긴 단일 페이지는 상태·전략·알림·성과·로그 하위 섹션으로 나눈다.
   - 설정값에는 단위와 설명을 붙이고, 운영 UI에서 바꿀 수 없는 값은 읽기 전용임을 표시한다.

## P2 — 품질 및 유지보수

10. **접근성 개선**
    - 탭에 `tablist/tab/tabpanel` 의미와 키보드 이동을 적용한다.
    - 입금 입력란에 보이는 `label`을 연결한다.
    - 버튼과 탭에 명확한 focus 스타일을 추가한다.
    - 넓은 표는 스크롤 가능하다는 단서를 제공하고 작은 화면에서는 카드/열 선택 방식으로 전환한다.

11. **시간·단위·언어 표준화**
    - ISO 문자열 대신 `08/26 15:20:24`처럼 읽기 쉬운 KST 표기와 기준시각을 사용한다.
    - 수익률에는 `%`, 금액에는 `원`, 비중에는 `%`를 항상 붙인다.
    - 내부 영문과 한국어 혼용을 제거한다.

12. **프런트엔드 구조 분리**
    - 현재 대시보드 HTML/CSS/JS가 한 Python 파일에 집중되어 변경 영향이 크다.
    - 화면 컴포넌트, 포맷터, API 상태 처리, 테이블/페이지네이션을 분리하고 렌더링 테스트를 추가한다.

13. **배포 구조 명확화**
    - 정적 GitHub Pages에서는 `/api/trader`가 없어 실제 입금/자동주문 상태를 제공할 수 없다.
    - 실제 대시보드는 인증된 백엔드와 함께 배포하고, 정적 보고서 링크와 운영 대시보드 링크를 구분한다.
    - 입금/주문 API를 외부 공개할 경우 인증, 권한, CSRF/요청 검증, 감사 로그가 필수다.

## 잘된 점

- 요청한 탭 순서와 중앙 페이지네이션(최대 5페이지)이 반영되어 있다.
- 표 헤더가 있고 손익 부호와 색상 구분이 일관적이다.
- 추천 기록과 가상 주문 데이터가 저장 계층에서는 별도로 관리될 토대가 있다.
- 가상계좌가 실제 API 주문이 아니라는 범위가 화면 설명에 드러난다.
